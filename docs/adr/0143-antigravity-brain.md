# 0143. The Antigravity brain: agents think with a person's Gemini plan through Google's Antigravity CLI

- Status: Accepted (2026-11-04; built: runner, engine, server, the shared client, the web and the phone app). The flags, events and files in §2–§5 are read from antigravity.google's docs and changelog (CLI 1.4.12), not yet run against a signed-in plan: the probes in §8 come before it ships. Amended 2026-11-11: §4 (one Gemini sign-in for all of its owner's agents where each is its own OS user, runner protocol 58).
- Date: 2026-11-04
- Extends: ADR 0032 (computer brains), ADR 0041 (accounts per agent), ADR 0053 §3 (permission profiles), ADR 0059 (AI accounts belong to people), ADR 0142 (the Grok brain, whose shape this mirrors), ADR 0137 §4 (the team's right hand on a plan)
- Amends: ADR 0142 ("Not done": Gemini through Antigravity is built)

## Context

Google's Antigravity CLI (`agy`) replaced the hosted Gemini CLI for personal accounts in 2026. It signs in with a personal Google account (Free, Google AI Pro, Ultra: `oauth-personal`) or a Gemini Enterprise seat (`oauth-business`), runs headless (`agy -p`), and its `--output-format stream-json` is its own NDJSON: one `init` (`conversation_id`, every tool's name, the permission mode), `step_update`s (`agent_response` text deltas with per-step usage, `tool` steps with `tool_info`'s call and output, `subagent_info`), one `result` (`status`, `response`, usage counted over the whole conversation, `finished_reason`).

Google's FAQ says: "Wrapping `agy` inside third-party coding agents or applications, or automating account rotation, is not supported under consumer plans" and "can result in suspension or termination of your account"; it recommends a Gemini Enterprise or AI Studio API key. ADR 0142 left it unbuilt for that. The owner decided (2026-11-04) to support personal plans like the other providers' with a plain warning, next to the API key (the model brain, already built) and Gemini Enterprise.

What the CLI does, read in antigravity.google/docs (cli/headless, cli/reference, install, ide/extensions/acp, mcp, permissions, subagents, cli/troubleshooting, plans, models, faq) and the changelog up to CLI 1.4.12 (2026-11-04):

- Settings in `~/.gemini/antigravity-cli/settings.json` (`toolPermission`, `enableTerminalSandbox`, `allowNonWorkspaceAccess`, `useG1Credits`, `disableSlashCommands`, `permissions.allow/ask/deny` as `action(target)`, `mcp(server/*)`); MCP servers in `~/.gemini/config/mcp_config.json` (and a workspace's `.agents/mcp_config.json`); global agents, rules, skills, hooks and plugins under `~/.gemini/config/`. No config-folder variable is documented.
- Sign-in: the OS keyring, or "the CLI's private secrets file"; on Linux it "bypasses the keyring when no D-Bus session bus is present" (1.2.x). `agy acp --login` signs in with Google "by pasting a code, then exit. Works over SSH". ACP's methods name `oauth-personal` and `oauth-business`, kept as `auth.type` in `settings.json`. `/logout` clears it. No status command.
- Headless flags: `--output-format stream-json`, `--model` (slugs such as `gemini-4-argon-high`, a model at one thinking level, as `agy models` lists them), `--effort` (low, medium, high), `--agent`, `--continue`/`-c`, `--conversation <id>`, `--mode accept-edits|plan`, `--sandbox`, `--dangerously-skip-permissions`, `--print-timeout`, `--disable-slash-commands`. A tool needing an approval in headless mode is soft-denied. An unknown `--conversation` only warns (1.2.x).
- Errors: a failed run exits non-zero; a model or agent failure exits 3 with `AGY_ERROR: {…}` on stderr (canonical status, HTTP or gRPC code, retryability, error id). `/usage` (quotas per model group, five-hour and weekly) is answered by the CLI itself in print mode.
- Plans: Google AI Pro (Gemini 4 Argon on paid plans, Gemini 3.8 Flash, Claude 5.5 models on non-trial), Ultra (the highest quota, refreshed every five hours, third-party models), Enterprise (also the older Flash and 3.1 Pro). AI credits past the quota only with `useG1Credits`.

## Decision

1. **A seventh computer brain** (`BrainKind` and `AccountKind` `antigravity`, `BRAIN_NAMES` "Antigravity CLI", `BRAIN_PLAN_NAMES` "Gemini", plan choice `gemini` with Gemini's mark), the same `brain.turn` as Grok's (`AntigravityBrain`, `ANTIGRAVITY_CLI`). Runner protocol 44 (`ANTIGRAVITY_PROTOCOL`): `brain.turn` `kind: "antigravity"`, `account` `kind: "antigravity"` (with `provider: "enterprise"`, `GEMINI_ENTERPRISE_PROVIDER`, for an Enterprise seat), `hello.executors.antigravity` (the version line and `agy models`), `access.tools.antigravity` (absent: follows Codex's). Missing CLI: `antigravity_missing`. No live steering. Usage is the person's plan (tokens recorded, cost zero).
2. **One `agy -p` per turn** (`brain-antigravity.ts`): `--output-format stream-json --sandbox --disable-slash-commands`; `work` adds `--mode accept-edits`, `plan` doesn't (an edit's approval never comes headless); `--model`, `--effort` (`xhigh`, `max` as high; none beside a slug that names its level), `--conversation` for a chat it knows. Our session → conversation per account in `antigravity-chats.json`; a new chat leads its prompt with the engine's context; a resume that comes back as another conversation is killed at `init` and started again with the context. Text from `agent_response` deltas, the CLI's tool steps as `tool_call` with their output (ours skipped), usage from the turn's `agent_response` steps (`result.usage` is the conversation's). `AGY_ERROR`'s `RESOURCE_EXHAUSTED`/429 or quota words are `plan_limit` with the reset the words give, `UNAUTHENTICATED`/401 or "authentication required" `not_logged_in`.
3. **Always an account, on Linux.** The account's folder is the CLI's whole `HOME` (and `XDG_*` under it, `XDG_RUNTIME_DIR` included so no session bus is found at `$XDG_RUNTIME_DIR/bus`), with no D-Bus session and no `DISPLAY` (X11's bus autolaunch), so the sign-in lands in its own secrets file there. Before every turn the runner removes what a turn could plant for a later one (`AGY_PLANTED`: global agents, skills, rules, plugins, hooks, project settings, `config.json`, the `GEMINI.md`/`AGENTS.md` rules) and writes `settings.json` (the sign-in type and an Enterprise seat's `gcp` kept; `proceed-in-sandbox`, sandbox on, nothing outside the workspace, `mcp(agenteschat_agentes/*)` allowed, no AI credits; slash commands stay on there, since turns pass `--disable-slash-commands` and `/usage` and `/logout` must reach the CLI rather than the model), `mcp_config.json` with our server alone (stdio `agentes-runner mcp`; the run and its token only in the env the server inherits, never in the shared file) and Lodi's agent. On macOS and Windows the CLI keeps every sign-in in the user's one keychain, so two accounts would be one: sign-ins and turns are refused there for now. `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_GEMINI_BASE_URL`, `GOOGLE_GENAI_*`, `GOOGLE_CLOUD_*`, `CLOUDSDK_*` and every `AGY_*` of the runner's env or the agent's secrets never reach it (only `AGY_QUIET_ENV`: no self-update, no logo). `GEMINI_`, `AGY_`, `GOOGLE_API_KEY`, `GOOGLE_GEMINI_*` and `GOOGLE_GENAI_*` are reserved secret names; Google Cloud's own (`GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_CLOUD_*`, `CLOUDSDK_*`) are not, and still reach agents on the other CLIs, which deploy with them.
4. **Accounts** (ADR 0041, 0059): `agy acp --login` in a new folder, its `accounts.google.com` link opened in the person's browser and the code Google shows pasted back, sealed to the computer's key like Claude's (`parseAgyLoginUrl`, `code`). `auth.type` is written before it: `oauth-personal`, or `oauth-business` when the person chose Gemini Enterprise under the sign-in. Status from `agy models` (models listed, no sign-in words) with the provider and the seat (`plan: "enterprise"`) from the settings; `agy -p /logout` before the folder goes. Plan usage by `agy -p /usage` (`antigravityUsage`: the first model group's five-hour and weekly windows, another group's as `other`). One login per agent; never made for all agents where each is its own OS user.

   *Amended 2026-11-11:* where each agent is its own OS user, a Gemini sign-in is made once for all of its owner's agents there, as Claude's and ChatGPT's are (ADR 0059 §2), from runner protocol 58 on (`SHARED_GEMINI_PROTOCOL`, `SHARED_SIGN_INS.antigravity`). What made it safe to share, read off the pinned CLI 1.5.0's binary: with no keyring to reach, the CLI keeps its Google sign-in in one plain JSON file, `.gemini/antigravity-cli/antigravity-oauth-token` (its access and refresh tokens and the plan's tier), written whole (600) and refreshed in place, tied to neither the OS user nor the computer, and `/logout` only deletes it. Google's refresh answers carry no new refresh token, so copies never sign each other out, unlike ChatGPT's rotating ones. So root signs in with `agy acp --login` in the account's folder, as before, keeps it (`<id>.shared`, never lent), and runs its status look and `/usage` there itself. Before the sign-in counts, root tries a copy: the file and the settings' sign-in type and seat in an empty home (`.check`), where `agy models` must list models (`agyCopyFails`); a copy the CLI says isn't signed in, or no file at all, ends the sign-in `failed` with `not_kept`, why in its error and the CLI's own words in `message`. The apps say why with the way out, a Gemini API key, and offer no Try again, which would end the same way (`geminiNotShared`). Signing in again that ends so leaves the account signed out for every agent, since its folder now holds that sign-in. A try that says nothing for sure (no answer in time, a copy that couldn't be written, any other error, such as no network) ends it `status_unknown` instead: the apps offer Try again, and nothing is signed out. Each turn's request carries a copy (`agy_auth` grant: the file's JSON, the type, an Enterprise seat's `gcp`), read between root's own CLI runs in that folder (`cliOps`), which refresh the file in place. The agent's worker writes it into the agent's own folder for the account and removes it once its last turn there ends (`holdAgySignIn`), and a worker starting removes any copy a killed one left (`dropAgySignIns`): the agent's user holds the sign-in only while its turns run, or, after its worker is killed mid-turn, until that agent's next worker starts, even if the account is removed meanwhile. No copy comes back to root. A turn the provider refuses marks the sign-in refused for every agent, as with any other sign-in for all agents. Older runners still lend a one-agent sign-in per turn; a one-agent login signed in again on a new runner starts over as one for all agents.
5. **The team's right hand** (ADR 0137 §4) on a Gemini plan: `--agent agenteschat-chat`, a global agent in the account's home with `tools: []`, `commandExecutionPolicy: off`, `subagent: false`, in an empty folder of its own (its `.agents/`, `.gemini/` removed) with none of the agent's secrets, sandbox on, no `--dangerously-skip-permissions`. The guard (`antigravityChatBreach`) kills the process on an `init` without a tool list or with any tool but our server's (`isOurAgyTool`), on anything before `init`, on a tool step that isn't ours and on any subagent: the turn ends `tools_not_locked`. Google's OAuth access and refresh tokens (`ya29.…`, `1//…`), API keys (`AIza…`) and client secrets (`GOCSPX-…`) join `scrubSignIns`.
6. **Apps.** Plan choice `gemini` (`PLAN_BRAIN` → `antigravity`, after Grok), Gemini's official mark, the paste-code steps on the web and the phone with "Usar o Gemini Enterprise" / "Usar uma conta pessoal do Google" under the sign-in, the phone's "Seu plano" listing Gemini, its models in "Quem pensa" (what `agy models` listed, else `ANTIGRAVITY_MODELS`: Gemini 4 Argon and 3.8 Flash at their levels, each with its catalog model), the tool switch in Ferramentas. The desktop app adds no Gemini accounts yet.
7. **The warning, said plainly** (a note, not an ⓘ) wherever a personal Gemini plan is connected or chosen: in Connect AI's sign-in steps and over an existing personal account there, and in the agent's AI section (the web's Quem pensa dialog and the phone's agent AI screen), in all 14 languages: "O Google diz que usar um plano pessoal do Gemini dentro de outros apps pode suspender a conta. Para não correr esse risco, use uma chave de API ou o Gemini Enterprise." (`connectAi.plan.gemini.warning`, `geminiPersonal`). An Enterprise sign-in shows only the usual "Atende outras pessoas" note, in a seat's words.
8. **Before it ships**, on a Linux computer with a Google AI Pro account and an Enterprise seat: that `agy acp --login` prints its link and takes the code on a pipe (else the runner drives it in a terminal, like `claude setup-token`) and honors `auth.type` from the settings for an Enterprise sign-in (its license picker), that the sign-in lands in the account's home with no D-Bus, that `agy models` and `agy -p /usage` answer as parsed, that the stdio MCP server inherits `AGENTES_MCP_RUN` and `AGENTES_MCP_TOKEN`, what `init` lists under `--agent agenteschat-chat` (MCP tool names, any lazy-MCP meta-tool, which the guard stops until it is known), the `AGY_ERROR` fields and a quota's words, whether `--mode accept-edits` with `proceed-in-sandbox` edits in the workspace without approvals, and that `agy -p /usage` and `agy -p /logout` are answered by the CLI (never sent to the model) with the account's settings.
9. **Install**: the core installs no coding CLI. Self-hosters run Google's installer (SELF_HOSTING.md); the Cloud image pins a release binary as `/usr/local/bin/agy` with `AGY_CLI_DISABLE_AUTO_UPDATE`, with a runner of protocol 44.

## Not done

- Gemini plans on macOS and Windows computers (the keychain is per user); the computer's own sign-in.
- A `plan` turn's sandboxed commands can still write in the workspace: the CLI has no per-run flag for a read-only sandbox, and the settings are shared by every turn on the account.
- The CLI's own telemetry has no settings key or flag outside ACP (`--disable-telemetry`): it stays as the account set it.
- The agent's shell sees the account's folder as its `HOME`, so a work turn's commands have no `~/.gitconfig` or SSH keys of the computer's user (the sandbox keeps them out anyway).
- Gemini through `agy` with an API key: the model brain already thinks with a Gemini key.

## Consequences

- A Gemini plan thinks for its owner's agents on a Linux computer whose runner is 44 or newer with the Antigravity CLI installed, and for Lodi locked to our server's tools, with Google's warning in plain sight wherever a personal plan is in play.
- Everything Antigravity-specific is behind runner protocol 44 and `kind: "antigravity"`: older runners and servers never see it.
